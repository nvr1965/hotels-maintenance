# hotelapp: приложение для гостиниц и сетей

Основа: код Ramada (PHP 8 + MariaDB, React 19 + Vite, PWA, Web Push, распознавание счётчиков). Ramada продолжает работать как есть, hotelapp ставится рядом в свою папку и свою базу.

## Устройство

- **Сеть → отели → объекты.** Отдельная гостиница = сеть из одного отеля.
- **Пользователь один на всю систему**, роль задаётся в каждом отеле отдельно (`hotel_members`): Исполнитель (worker), Менеджер (manager), Руководитель (head) и флаг «Администратор отеля» (бывший sysadmin).
- **Роли сети** (`org_members`): Администратор сети (все отели сети как администратор отеля, заводит новые отели) и Наблюдатель (все отели сети, только отчёты, роль `viewer`).
- **Владелец системы** (`users.is_superadmin`): все сети, создаёт новые сети.
- **Текущий отель** хранится в сессии; переключение `select_hotel.php`. Все данные (объекты, справочники, заявки, регламенты, счётчики) с `hotel_id`.
- **Настройки отеля вместо зашитого кода**: название и заголовки на 4 языках, подпись, цвета, логотип, часовой пояс (PHP и MySQL `NOW()`), языки, прочее в `settings_json` (кому слать уведомления, распознавание счётчиков).
- **Справочники у каждого отеля свои**; новый отель можно создать копией справочников другого.
- Пароли базы в `backend/core/config.local.php`, ключи сервисов в `secrets.php` / `push_keys.php`. Ни то, ни другое в пакеты не входит.

## Этапы

1. **Основа (готово, пакет `hotelapp-stage1`)**: схема базы, вход и сессии, отели и роли, API сети (`net_admin.php`), брендинг до входа, перенос данных Ramada (`tools/migrate_ramada.php`).
2. **Перенос API (готово)**: все файлы `backend/api` Ramada на `app_require()` и `hotel_id`; уведомления по членам отеля; ссылки на отчёт по счётчикам у каждого отеля; загрузки в `uploads/h<id>/`; закрыть доступ без входа (в Ramada так открыт `save_checklist.php`).
3. **Интерфейс (готово, пакет `hotelapp-stage2-3` вместе с этапом 2)**: брендинг из настроек (логотип, цвета, заголовки, иконка и имя на телефоне), выбор отеля в меню ☰, вкладка «Сеть и отели» в админке (настройки и оформление отелей, новый отель с копией справочников, люди в отелях, администраторы и наблюдатели сети), наблюдатель видит только отчёты. Позже: сводные отчёты сразу по всем отелям сети.
4. **Запуск рядом с Ramada**: свой адрес (тестовый поддомен через Cloudflare), проверка на свежей копии данных (`--replace`), затем решение о переключении.

Дальше по желанию: больше языков (таблица переводов вместо колонок *_ru/_en/_he/_ar), шаблоны справочников на уровне сети, регистрация новых сетей.

## API этапа 1

| Файл | Что делает |
|---|---|
| `login.php` | POST `{username, password, lang, remember}` → пользователь, текущий отель, список отелей |
| `me.php` | то же для уже вошедшего; 401 — не вошёл |
| `select_hotel.php` | POST `{hotel_id}` — переключить отель |
| `set_lang.php` | POST `{lang}` |
| `logout.php` | выход |
| `branding.php` | GET `?hotel=<slug>` — брендинг для экрана входа |
| `net_admin.php` | сети, отели, люди и роли (см. шапку файла) |

В новых API: `require_once __DIR__ . '/../core/api.php'; $me = app_require(['head']); $hid = $me['hotel_id'];` и `WHERE hotel_id = ?` во всех запросах. Хелперы запросов: `db_one`, `db_all`, `db_value`, `db_exec` (только подготовленные запросы).
